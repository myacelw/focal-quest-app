# 限时挑战模式 · 设计文档

日期：2026-07-26
状态：已获用户批准（5 个关键决策经确认：数据去向 / 游戏形态 / 奖励与入口 / 难度自适应 / 总时长 30 秒）
来源：迭代 2 的遗留项。需求文档 §117 原话是"迭代 2 增加可选的**限时挑战**模式（固定节拍逐渐加速，用于冲 CPM）"，CLAUDE.md 标注"需确认节奏"——本文档就是把那个节奏确认下来。

## 1. 定位

练完当天正经训练后解锁的**小游戏关**：30 秒冲分，练腻了换口味用。

**不是**提速训练模式。它的数据不进任何统计、不给任何奖励。

## 2. 关键决策（用户已确认）

| 决策 | 选择 | 理由 |
|---|---|---|
| 数据去向 | **单独记录，不进统计** | 挑战里节拍压过真实调节速度时孩子会瞎猜——答对率数字还在但不再代表调节能力。不进统计，瞎猜的唯一代价就是分数低，家长看的趋势图永远干净 |
| 游戏形态 | **30 秒冲分** | 时长可控（不会玩太久伤眼）、有加速的紧张感、失误不致命。生存模式一次失误就结束太挫败，且可能连对很久而玩过头。（初定 60 秒，用户认为偏长，改 30 秒） |
| 奖励与入口 | **不给奖励 + 当天练完才解锁** | 挑战比正经训练好玩且只要 30 秒。若给积分（能换现实奖励和补签卡）或随时可玩，孩子会刷挑战、足不经心做正经训练——那就本末倒置了。锁在训练之后，挑战就成了训练的奖赏而非替代品 |

## 3. 医学设定

### 3.1 双眼进行，不遮眼（与正经训练的关键区别）

挑战**不分左右眼、不遮眼**。依据：**双眼调节灵敏度训练（binocular accommodative facility）本身就是标准训练项目之一**，不是为简化流程而编的借口。附带好处：30 秒不必切成两眼各 15 秒（太碎），且与正经训练（单眼遮眼）形成天然区分，两边数据不会混淆。

### 3.2 翻拍照旧要真翻（不可妥协的底线）

挑战全程保留翻拍引导。**翻拍过渡时间沿用设置里的值，但强制不低于 600ms**（600ms 正是设置里最快档，即用户已认可的下限）。

为什么这条不能松：若节拍快到孩子来不及真翻拍，她就会干脆不翻——挑战退化成纯反应游戏，与视力训练无关，更糟的是会让她养成"不翻拍也能玩"的习惯，反过来腐蚀主流程。宁可挑战不够刺激，也不能让它教坏主流程。

### 3.3 视标尺寸不因挑战而变

视标物理尺寸仍是 `毫米设定 × 屏幕标定`，与正经训练完全一致，不因"挑战要更快"而调小。挑战调的是**给多少时间**，不是**看多小的字**。

## 4. 节奏：按孩子实测反应时间自适应

### 4.1 为什么不用固定常量

项目从"专业性增强"迭代起就在落库 `avgReactionMs`（视标出现 → 答对的实测反应时间）。用它定节拍比拍脑袋准，而且**孩子练进步、反应变快后挑战会自动变难**，不需要人回来调常量——这正契合本功能"冲 CPM"的初衷。

初稿写的是固定 4000ms 起、2000ms 下限，按"反应时间 1.5 秒"假设推出。用户反馈孩子实测**约 1 秒或更快**，那 4000ms 相当于宽松系数 3.1——前十几题几乎没有压力。故改自适应。

### 4.2 关键语义修正：时限只覆盖答题窗口

初稿把翻拍过渡算进了"每题时限"，导致 900ms 固定开销吃掉大半空间（2.5 秒时限里只有 1.6 秒真正用于答题），加速感被压扁。

**现在的定义**：每题时限 = 从视标出现到必须答出的**答题窗口**；翻拍过渡是它之后的独立阶段，**不计入时限、也不被压缩**（§3.2 的 600ms 底线仍然有效）。

### 4.3 参数

| 参数 | 值 | 说明 |
|---|---|---|
| 总时长 | **30 秒** | |
| 反应时间基准 | 最近 20 次训练的 `avgReactionMs` **中位数** | 用中位数而非平均，避免个别走神的题拉偏 |
| 初始答题窗口 | 基准 × **2.0** | 按 1 秒基准 = 2000ms，每题总耗时约 2.9 秒 |
| 最快答题窗口 | 基准 × **1.3** | 按 1 秒基准 = 1300ms，每题总耗时约 2.2 秒 |
| 加速节奏 | 每 **3** 题降一档 | 30 秒约答 11-13 题，每 5 题只够触发两次，太少 |
| 每档减少 | `(初始 − 最快) / 4`，四档到底 | 按 1 秒基准 = 每档 175ms |

**下限系数不得低于 1.3**：`avgReactionMs` 是平均值、实际有波动，压到 ×1.05 会让约一半的题超时——那就是逼孩子瞎猜。这条与 §3.2 的翻拍底线同级，是本设计的医学边界。

### 4.4 兜底与钳制

- **数据不足**（训练次数 < 3 或无 `avgReactionMs`）→ 用固定默认：初始 2000ms、最快 1300ms（即按 1 秒基准）
- **钳制区间**（防异常数据算出荒谬值）：初始窗口钳在 `[1500, 4000]`ms，最快窗口钳在 `[1000, 2500]`ms
- 全部系数与区间集中在一处常量，实测后改这里

### 4.5 超时的语义

超时 = 未答：**不算错，也不得分**，直接下一题。答错与超时都会清零连击，区别只在计数上（分别记入"答错数"与"超时数"，结算页分开显示，好让孩子知道自己是看错了还是没跟上）。两者都不影响正经训练的正确率——因为挑战根本不落 `sessions` 表。

## 5. 数据

**最高分存 localStorage（`fzp.challengeBest`），不进 Dexie、不同步。**

为什么不落库：若塞进 `sessions` 表加个 `mode` 字段，则所有统计查询（`aggregate` / `period` / `weekly-report` / 勋章判定 `deriveStats` / 首页 `getHomeStats`）都必须记得过滤掉挑战行——**漏一处就污染趋势图**，而这正是迭代 3c 评审反复警告的失败模式（按维度过滤漏一处就串数据）。挑战数据的价值远不值这个风险。

代价：换设备丢最高分。可接受——那是"玩"的数据，不是训练记录。若将来真想同步，再作为独立 kind 加，不要混进 sessions。

## 6. 架构

```
src/challenge/
  challenge-session.ts       纯函数状态机：时限递减、计分、超时判定
  challenge-session.test.ts
  challenge-storage.ts       最高分读写（localStorage，lsGet/lsSet）
  challenge-storage.test.ts
  ChallengePage.tsx          挑战页（App 的新 View 分支）
  ChallengeCard.tsx          首页入口卡（仅当天已完成训练时渲染）
```

**不复用训练的 `session.ts`**：两者规则不同（挑战有每题时限、不分眼、不落库），强行合并会把那个已被大量测试验证的训练状态机搞复杂，风险不对等。

**复用**（均已核实存在）：皮肤 Stage（`src/skins/registry.ts` 的 `skinById`，挑战也能换肤）、`TumblingE`（`src/training/TumblingE.tsx`）、`playSfx`（`src/training/sfx.ts`）、`pickDirection`（`src/training/session.ts:33`）、翻拍引导的视觉与 CSS（`.fzp-*` 类，`src/index.css`）、`lsGet/lsSet`（`src/data/storage.ts`）。

## 7. 解锁条件

当天已完成正经训练（即 `checkins` 里有今天的行）→ 首页出现挑战卡。否则不渲染入口，挑战页也不可达。

判定复用现有的 `getHomeStats(today)`——已核实它返回 `{ checkedInToday, streak, totalPoints }`（`src/data/checkin.ts:50`），且 IndexedDB 不可用时降级为 `checkedInToday: false`（即降级时挑战入口不出现，安全方向）。解锁判定本身抽成纯函数便于单测。

## 8. 测试策略

- `challenge-session.ts`：时限递减序列、下限钳制、计分、超时不算错、总时长结束判定、自适应时限推导 —— 纯函数全覆盖
- `challenge-storage.ts`：最高分读写、首次无值、破纪录判定
- 解锁条件：有/无今日打卡两种情况
- UI 不写测试（项目没装 jsdom），改为手测清单

## 9. 明确不做

- **不给积分/勋章/怪兽**（§2 理由）
- **不进统计、不同步、不落 Dexie**（§5 理由）
- **不做排行榜**（单机家用，无社交需求）
- **不做手动难度档位**（用户已选自适应：难度由 §4 的实测反应时间自动推导，不给"轻松/标准/狠"这类选项，省一个设置项与一层交互；要整体调松紧就改 §4 的系数）
- **不做左右眼分别挑战**（§3.1 双眼进行）
- 不引入游戏引擎（项目既有边界：DOM + CSS）

## 10. 风险

| 风险 | 应对 |
|---|---|
| 节拍仍偏快导致孩子瞎猜 | 数据不进统计，无污染；实测后调 §4 常量 |
| 孩子沉迷挑战、轻视训练 | 锁在当天训练之后 + 不给奖励；若仍失衡，把总时长砍到 20 秒或提高解锁门槛（如需连续打卡才给玩） |
| 30 秒高强度用眼 | 时长固定且短；解锁条件保证它发生在训练之后而非之前 |
| 挑战被当成训练成绩 | UI 文案明确"这是小游戏，不算训练成绩" |
